# Building and installing SwiftDM (Debian 13 / trixie)

SwiftDM builds with CMake and installs through the standard CMake install rules
or as a `.deb` package generated by CPack. Both paths install the same files:

| Path | File |
|---|---|
| `/usr/bin/swiftdm` | application and headless `get` CLI |
| `/usr/share/applications/swiftdm.desktop` | launcher entry |
| `/usr/share/icons/hicolor/<size>/apps/swiftdm.png` | launcher icon (16–512 px) |
| `/usr/share/metainfo/io.github.swiftdm.SwiftDM.metainfo.xml` | AppStream metadata |
| `/usr/share/doc/swiftdm/copyright` | Apache-2.0 license text |
| `/usr/share/swiftdm/chromium/` | Chromium extension (load unpacked) |

> The launcher icons are rendered during the build, so a headless-only build
> (`-DSWIFTSDM_BUILD_UI=OFF`) installs the desktop entry without an icon.

## 1. Dependencies

```sh
sudo apt install build-essential cmake file ninja-build \
    qt6-base-dev qt6-svg-plugins libqt6svg6 \
    libcurl4-openssl-dev libsqlite3-dev
```

`qt6-svg-plugins` is needed at build and run time: the toolbar, window and tray
icons are SVG resources loaded through Qt's image plugin. `file` is required by
CPack's Debian generator when it computes the shared library dependencies with
`dpkg-shlibdeps`.

## 2. Build and test

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
```

Run the freshly built binary with `./build/swiftdm` (GUI) or
`./build/swiftdm get <url>` (headless).

## 3. Install as a `.deb`

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
cd build && cpack
```

This writes `swiftdm_<version>_amd64.deb` into the build directory. Install it
with:

```sh
sudo apt install ./build/swiftdm_0.18.19_amd64.deb
```

`apt` resolves only the runtime dependencies (`libqt6*`, `libcurl4t64`,
`libsqlite3-0`, `libqt6svg6`, `qt6-svg-plugins`). They are computed from the
binary by `dpkg-shlibdeps`, so the package stays correct when the build host's
library versions change. The package declares no browser dependency: browser
integration is optional, and the extension can be loaded into any
Chromium-based browser (Chrome, Chromium, Edge, Brave).

Confirm that the generated package has no browser or printer recommendations:

```sh
dpkg-deb -f build/swiftdm_0.18.19_amd64.deb Depends Recommends Suggests
```

`Recommends` and `Suggests` should be empty. Use `--no-install-recommends`
only when you also want to skip recommendations from Qt and other libraries;
keep desktop platform plugins such as `qt6-wayland` installed.

Remove it again with `sudo apt remove swiftdm` (configuration and download
history stay in `~/.config/swiftdm` and `~/.local/share/swiftdm`).

## 4. Install with CMake (no package)

```sh
sudo cmake --install build --prefix /usr/local
```

Use `--prefix /usr` for a system-wide install that matches the `.desktop` and
icon paths expected by desktop shells. Installing under `/usr/local` also works
because the desktop entry uses an icon-theme name, but the AppStream metadata is
only picked up from `/usr/share`.

## 5. After installing

- The launcher entry appears in the application menu as **SwiftDM**.
- The browser extension lives in `/usr/share/swiftdm/chromium`. Load it from
  `chrome://extensions` with **Load unpacked**, or keep using the checkout in
  `ext/chromium` while developing.
- Closing the main window hides the app in the tray; quit from the tray menu.

## Regenerating icons

The launcher icons are rendered from `ui-assets/app-icon/main-icon.svg` during
the build, so a changed app icon is picked up by the next
`cmake --build build` and ends up in the installed icons and in the package.
The rendered PNGs are written to `build/generated/icons/hicolor/`.

The Chromium action icons are still generated on demand:

```sh
cmake --build build --target render-extension-icons
```
